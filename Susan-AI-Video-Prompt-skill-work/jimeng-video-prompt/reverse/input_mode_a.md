# 反推·输入模式A：视频文件输入

## 适用场景

用户直接给了视频文件（.mp4/.mov等），需要通过技术手段提取信息后再反推。

## 适用环境

- Claude Code（CC）：支持bash工具，可执行ffmpeg/whisper
- Codex：同上
- Gemini：原生支持视频理解，无需预处理

## 处理流程

### Step 1：元数据提取

```bash
ffprobe -v quiet -print_format json -show_format -show_streams 视频文件.mp4
```

提取关键信息：
- 时长（duration）→ 判断是单段还是多段
- 分辨率（width/height）→ 确认画幅比例
- 帧率（fps）→ 用于截帧密度决策

### Step 2：逐帧截图

```bash
ffmpeg -i 视频文件.mp4 -vf fps=2 frame_%04d.jpg
```

- 15秒视频用fps=2，产出约30帧，足够分析
- 30秒视频用fps=1，产出约30帧
- 截图后逐帧分析内容（人物、动作、产品、场景、表情）

### Step 3：语音转文字（如有台词）

```bash
whisper 视频文件.mp4 --language zh --model medium
```

- 仅在视频有口播台词时执行
- 如果是沉浸式无台词视频，跳过此步
- 如果是非中文台词，调整`--language`参数
- 转写结果需人工校对，whisper可能有误差

### Step 4：信息汇总→进入V3反推流程

将以上提取的信息汇总后，进入 `reverse/v3_reverse_core.md` 的反推流程：
- 帧图 → 用于分析6维度中的②镜头③动作④场景⑤色调⑥细节
- 台词文字 → 用于分析①人物（口播台词部分）
- 元数据 → 用于确定时长、分镜切分

---

## 注意事项

1. **不要跳过截帧直接"看"视频**：AI无法直接播放视频，必须通过截帧转为图片后逐帧分析
2. **截帧密度要够**：fps=2是最低标准（每秒2帧），如果视频动作变化快（如卡点换装），建议fps=3
3. **关键帧标注**：截帧后先快速浏览所有帧，标注出"关键动作变化帧"（如咬下食物、掰开包子、转身等），这些帧的分析权重最高
4. **Gemini环境**：如果在Gemini中使用，可以跳过ffmpeg步骤直接上传视频让Gemini分析，但仍需按V3反推流程的6维度进行结构化拆解
